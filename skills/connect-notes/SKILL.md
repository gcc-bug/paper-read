# Connect notes

Read [AGENTS.md](../../AGENTS.md). Start from the requested note, concept, or
question and read enough of it to understand its mechanism and assumptions.

Search existing notes using alternative terminology, shared assumptions,
mechanisms, and mathematical structures. Consider support, contradiction,
extension, generalization or specialization, use of an idea, and analogy. Check
whether a new source answers an older question. Shared keywords alone do not
establish a useful relationship.

Inspect both sides before asserting a connection. Follow source references when
needed; if only reading notes are available, identify that evidence limitation.
Explain the relation's direction, common structure, relevant differences, and
why the connection could matter. Preserve incompatible assumptions rather than
making sources appear to agree.

Distinguish:

- **Strong connection:** directly supported by identifiable evidence on both sides.
- **Plausible connection:** a meaningful shared mechanism with unresolved evidence
  or assumptions; label an unverified Codex proposal as a hypothesis.
- **Speculative analogy:** a potentially useful resemblance with substantial
  differences; label it explicitly and say what would test it.

Strength is not the same as verification. Give confidence with reasons, and do
not change a hypothesis to verified without supporting evidence. Record what
would weaken the proposed relationship as well as what would strengthen it.

Search for an existing connection before creating one. Use
[the connection template](../../templates/connection.md) only when the relationship
deserves its own note. Otherwise keep a brief suggestion in the originating note
or report no useful connection. Do not manufacture a quota of links.

For new standalone notes, use relative links to both sides and add a relevant
backlink in their connection sections without rewriting personal text. Update
existing questions when evidence answers or changes them; retain their history.
Apply [Automatic commits](../../AGENTS.md#automatic-commits), keeping connection
notes and their backlinks in one focused commit. When this workflow is part of
reading or review, let the parent task commit the combined result. A search that
changes no files needs no commit. Summarize the useful relationships,
uncertainties, changed paths, and commit hash/subject (or why no commit was made).
